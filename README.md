# B站评论管家（BiliComment Keeper）

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Manifest](https://img.shields.io/badge/manifest-v3-brightgreen.svg)](manifest.json)
[![Chrome](https://img.shields.io/badge/chrome-111%2B-yellow.svg)](#一安装chrome--edge)
[![Dependencies](https://img.shields.io/badge/dependencies-0-success.svg)](manifest.json)
[![检查](https://github.com/cshskdjskwj/bili-comment-keeper/actions/workflows/check.yml/badge.svg)](https://github.com/cshskdjskwj/bili-comment-keeper/actions/workflows/check.yml)

弥补 B 站没有「查看自己的评论历史」的功能。

**它做四件事：**

1. **自动记录** —— 你在 B 站发出任意一条评论（含楼中楼回复），扩展会立刻拿到这条评论的永久链接，
   存进浏览器里自动创建的目录 `其他收藏夹 / 评论管家 / B站我的评论`，标题统一格式：
   `[2026-01-30 12:34] BV1xx411c7mD · 哈哈哈哈这个太好笑了`
2. **一键清除** —— 打开清除面板，逐条调用 B 站官方删除接口删掉这些评论；
   每删成功一条，对应书签就**原封不动**移动到 `B站已删除评论` 目录。
   删失败的会留在原目录并在日志里写明原因，绝不会"以为删了其实没删"。
3. **手动删除也同步** —— 你直接在 B 站网页上点某条评论的「删除」（不走扩展面板），
   扩展同样会把那条书签归档到 `B站已删除评论`。不管你从哪删的，账始终是平的。
4. **补上装扩展之前的历史评论** —— 从 [aicu.cc](https://www.aicu.cc) 把历史评论清单导进来，
   并进同一个待删列表。装扩展之前发的、手机上发的，就靠这个补。

书签目录长这样：

```
其他收藏夹/
└── 评论管家/
    ├── B站我的评论/        ← 发出的评论记录在这里
    └── B站已删除评论/      ← 删掉的评论，链接原封不动搬到这里
```

放「书签栏」还是「其他收藏夹」、外层文件夹叫什么，都能在设置里改。
（如果之前版本已经把目录建在了书签栏顶层，扩展会自动把整个目录搬进 `评论管家`，里面的书签一条都不会丢。）

### 为什么存进书签里？（设计巧思）

因为浏览器自带**云同步**。Chrome / Edge 登录账号后，书签会自动同步到云端、覆盖你的所有设备。

于是这个扩展顺手把浏览器的账号体系当成了**免费云端存储**：

- 不用注册、不用服务器、不用数据库，**零后端成本**
- 换电脑 / 重装浏览器，登录账号后评论记录自动回来（连那两个目录一起）
- 手机上的 Chrome 也能翻到自己发过的评论链接，点开直接跳转
- 数据存在你自己的浏览器账号里，不经过任何第三方服务器
- 「已删除」归档同样同步，所以在任何设备上都能核对删过哪些

> 前提是浏览器登录了账号并开着同步。没登录的话，书签只存在本机。

补充一点：书签本身只管「链接和标题」，而删除评论还需要知道这条评论属于哪个评论区（`oid` / `type`）。
这两个字段扩展会额外备份进浏览器的同步存储，换设备后连删除功能也能照常工作。
备份只存这两个字段，约 2000 条以内都没问题；一旦超过同步配额，**设置页会明确写出失败原因**，
本地记录和书签完全不受影响 —— 不会像以前那样悄悄坏掉。

## 一、安装（Chrome / Edge）

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 回车
   （Edge 是 `edge://extensions/`）
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序**，选中本文件夹 `bili-comment-keeper`
4. 装好后工具栏会出现「B站评论管家」图标。角标数字 = **「已删除」归档里还有几条没清空**（刚装上是 0，所以不显示）

> 需要 Chrome 111 或更高版本（用到了 MV3 的主世界内容脚本特性）。
> 没有图标文件，Chrome 会显示默认的拼图图标，不影响任何功能。

### 它要了哪些权限？

装之前 Chrome 会弹权限提示，这里逐条交代，没有一条是多余的：

| 权限 | 用来干什么 | 为什么绕不开 |
| --- | --- | --- |
| `bookmarks` | 建立并读写「B站我的评论」「B站已删除评论」两个目录 | 记录、归档，以及删除成功后移动书签 |
| `storage` | 存一份 rpid → 评论区 id 的索引，以及从 aicu.cc 导入的历史评论清单 | 删评论时要告诉接口这条评论属于哪个评论区（视频 aid） |
| `scripting` | 往 bilibili 标签页注入一小段脚本 | 删除请求必须从 bilibili 页面里发出去，否则登录态 Cookie 会被 SameSite 拦掉 |
| 主机权限 `https://*.bilibili.com/*` | 在 B 站域名下运行 | 抓评论接口、发删除请求都只发生在 B 站 |
| 主机权限 `https://*.aicu.cc/*` | **只在你自己打开 aicu.cc 时**运行，把页面上已经加载出来的评论列表读走 | 见下方「aicu.cc 导入」一节 |

**故意没有申请的权限**（这些才是该警惕的）：

- ❌ `tabs` / `webNavigation` —— 读不到你的浏览历史
- ❌ `webRequest` / `declarativeNetRequest` —— 不能监听或篡改你的网络请求
- ❌ `<all_urls>` —— 只在 B 站和 aicu.cc 上运行，别的网站一概不碰
- ❌ 远程代码 / 外部服务器 —— 零依赖、零上报，所有代码都在本地

`bookmarks` 确实能看到你的全部书签，这是权限本身决定的、绕不开。扩展的行为边界是：
**只在自己创建的那两个目录里增删书签**。查找这两个目录时，极端情况下（比如你把目录手动挪走了）
会调用 `bookmarks.search` 按**目录名**做一次全局查找，但只比对目录名这一个字段，
不会读取、更不会上传任何书签内容。

**关于 aicu.cc 那条权限**：扩展在 aicu.cc 上**不会替你发任何请求**，只是挂钩页面自己的
`fetch` / `XMLHttpRequest`，把页面**已经拉回来**的评论列表读一份走 —— 和你打开页面看到的是同一份数据，
不会给 aicu.cc 增加任何额外负载。

## 二、怎么用

### 记录

正常刷 B 站、正常发评论就行，不需要任何额外操作。

发完之后：
- 点开弹窗能看到两个数字：**待清理评论**（还没删的）和 **归档待清空**（已删的，等于角标数字）
- `其他收藏夹 / 评论管家 / B站我的评论` 里出现刚发的那条评论链接
- 角标**不会变** —— 角标数的是「已删除、还没清空归档」的条数，删掉一条评论才会 +1

楼中楼回复也会被记录，链接格式和 B 站自己的「复制评论链接」完全一致：

```
一级评论
https://www.bilibili.com/video/BV1xx411c7mD?comment_on=1&comment_root_id=123456789012&share_tag=s_i#reply123456789012

楼中楼
https://www.bilibili.com/video/BV1xx411c7mD?comment_on=1&comment_root_id=123456789013&comment_secondary_id=123456789014&share_tag=s_i#reply123456789014
```

### 一键清除

1. 点工具栏图标 → **一键清除**（会打开一个独立面板页）
2. 面板里列出所有记录，可以取消勾选不想删的
3. 点 **开始删除**，看进度条和日志走完
4. 删成功的会自动移到 `其他收藏夹 / 评论管家 / B站已删除评论`，同时**工具栏角标 +1**
5. 归档堆多了想清理，面板底部的「**已删除归档**」区块里点 **一键清空** ——
   会二次确认（8 秒不操作自动取消），确认后把归档目录里的书签全部删掉，目录本身保留，**角标随之归零**

> 注意区分两个「删」：面板主列表的「开始删除」删的是**B 站上的评论**；
> 归档区块的「一键清空」删的是**本地书签**。书签删掉就找不回来了，所以有二次确认。

别关那个面板页，关掉 = 中止。

### aicu.cc 导入（补上装扩展之前发过的评论）

本扩展只能记录**装好之后**发出的评论 —— 装之前发的、在手机 App 上发的，它一无所知。
如果想把那些也清掉，可以从 [aicu.cc](https://www.aicu.cc)（一个第三方 B 站评论查询站）把历史清单导进来。

**怎么用：**

1. 在浏览器里打开 `https://www.aicu.cc/reply?uid=你的UID`（把 UID 换成你自己的）
2. **翻几页**（列表是分页拉的，扩展只读你实际翻到的那几页），弹窗里会实时显示已导入多少条
3. 点工具栏图标 → **一键清除**，面板中间会出现「**aicu.cc 导入的历史评论**」区块
4. 点 **全部加入待删列表** —— 它们会并入上面的主列表，之后走的是**完全相同**的删除流程
5. 勾选 → **开始删除**

**几点必须说清楚：**

- **aicu.cc 只是索引，评论实体在 B 站。** 删除永远发生在 B 站，不可能从 aicu 的存档里删东西；
  而且这类站点往往自己留了副本，你把 B 站评论删了，它的存档也未必跟着消失。
- **绝大多数条目可能早就被删过了。** 这种情况接口会返回 `12022 该评论已经被删除`，
  扩展把它当作「已经没了」记账，并从导入清单里移除，**不会重复处理**。
  顺带一提：删除接口本身就是「这条还在不在」的唯一可靠判据，所以没法跳过探测、也没法加速。
- **每条都要真调一次接口**，默认间隔 1.5~4 秒。几千条会跑很久 —— 开始前面板日志里会给出预计耗时。
  中途可以点 **停止**，已经处理过的会记账，回来接着跑不会重头再来。
- 已经躺在本扩展「已删除」归档里的条目，合并时会**直接跳过**，不浪费那次请求。
- 面板会显示导入清单里的 UID 并提醒你核对。**B 站的删除接口只可能删掉你自己的评论**，
  但为了不越界，请确认导进来的是你自己的账号。

## 三、它是怎么做到的

| 环节 | 实现 |
| --- | --- |
| 抓评论链接 | `src/recorder-main.js` 在页面主世界挂钩 `fetch` / `XMLHttpRequest`，只偷看 `POST /x/v2/reply/add` 的成功响应，从里面取 `rpid / root / parent`，再用当前页面地址拼出评论链接 |
| 兜底 | 可选：同时监听剪贴板，你手动点 B 站「复制评论链接」时也会被记录（默认关闭，见下方说明） |
| 写书签 | `src/background.js` 用 `chrome.bookmarks` 建目录、写书签；书签 API 只有扩展能用，油猴脚本没有这个权限 |
| 删除 | `clean/clean.js` 往一个 bilibili 标签页注入脚本，由**那个页面**发 `POST /x/v2/reply/del`（`type / oid / rpid / csrf`） |
| 同步手动删除 | `src/recorder-main.js` 同时监听 `/x/v2/reply/del` 的成功响应；你在网页上自己删评论时，`src/background.js` 按 rpid 找到对应书签并移进「已删除」目录（只动「我的评论」目录里的书签，不碰你别的收藏） |
| 归档 | 删除成功后 `chrome.bookmarks.move()` 把书签移到「已删除」目录，URL 一个字符都不改 |
| **aicu 导入** | `src/aicu-main.js` 在 aicu.cc 的主世界挂钩 `fetch` / `XMLHttpRequest`，把页面**已经拉回来**的 `/api/v4/search/getreply` 响应读走。它的 `rpid` / `dyn.oid` / `dyn.type` 正好就是 B 站删除接口要的三个参数，所以导入清单能直接走上面同一套删除流程，一个字都不用改 |

**为什么删除请求非要绕到 bilibili 页面里发？**
扩展页面的来源是 `chrome-extension://`，对 `bilibili.com` 算跨站，`SESSDATA` 这类 Cookie 会被 SameSite 规则拦掉，直接发必然未登录。
在 bilibili 页面里发就是同站请求，和 B 站自己前端发的请求一模一样。

## 四、设置项

点图标 → 设置（或 `chrome://extensions/` 里的「扩展程序选项」）：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 自动记录评论 | 开 | 关掉后发评论不再写书签 |
| 放在哪里 | 其他收藏夹 | 可选「书签栏」或「其他收藏夹」，默认不占用书签栏 |
| 外层文件夹名 | `评论管家` | 两个评论目录都装进它里面；留空则直接放在上面选的位置下 |
| 存活评论目录名 | `B站我的评论` | 建在外层文件夹里面 |
| 已删除评论目录名 | `B站已删除评论` | 删除后书签移到这 |
| 标题里带评论正文 | 开 | 带正文更好翻，关掉就只留日期和 BV 号 |
| 剪贴板兜底 | 关 | 打开后，你手动点「复制评论链接」也会补记一笔。**代价**：复制别人的评论链接分享时也会被记进目录 |
| 删除间隔 | 1500 ~ 4000 毫秒 | 每条之间随机等待，太快会触发风控 |

## 五、常见问题

**Q：发完评论书签没出现？**
- 看图标角标有没有 +1；没有的话打开设置确认「自动记录评论」是开的
  （提醒：发评论**不会**让角标变化，角标只在删掉评论后 +1）
- 刚装完扩展时，**已经开着的旧标签页不会生效**，刷新一下那个页面（或重新打开）再发
- B 站偶尔会改接口路径。真漏了可以在设置里打开「剪贴板兜底」，然后手动点一下那条评论的「复制评论链接」补记

**Q：我在 B 站网页上自己删了评论，书签会怎样？**
会自动从「B站我的评论」移到「B站已删除评论」，和用面板删的效果完全一样。
前提是删的那一刻那个页面加载着扩展（扩展装好后**新打开或刷新过**的页面）。
如果是在手机 App 上删的，扩展不知道，那条书签需要你在面板里删一次——
会返回 `12022 该评论已经被删除了`，面板照样把它归档，不会卡住。

**Q：删除时报 `-509 请求过于频繁`？**
触发了风控。代码会自动等 15 秒重试一次；还失败就把设置里的间隔调大（比如 4000~8000 毫秒），过一会儿再点「重试失败项」。

**Q：报 `-101 账号未登录` / `-111 csrf 校验失败`？**
浏览器里的 B 站登录态过期了。重新登录 B 站，然后重试。

**Q：报「缺少评论区 oid」？**
说明这条记录的元数据丢了（比如扩展被卸载重装过）。视频评论会自动用 BV 号反查 aid，一般能救回来；
非视频页面（动态、专栏）如果反查不到，就把那条书签留着手动删。

**Q：一次删太多会不会封号？**
删的是你自己的评论，属于正常操作。但短时间高频操作确实可能触发风控（表现为 -509），
所以默认加了随机间隔。几百条建议分批来。

**Q：`B站已删除评论` 里为什么链接还和原来一样？**
故意的。原样保留链接才能事后核对「到底删没删」，你可以随时点开确认。

**Q：aicu.cc 导入区一直是 0 条？**
扩展只读你**实际翻到**的那几页，没有翻页就不会有数据。另外注意两点：
（1）刚装好或刚更新扩展时，**已经开着的 aicu 页面不生效**，刷新一下再翻页；
（2）如果翻页时报错或列表一直转圈，那是 aicu 自己的排队/验证没过，与本扩展无关 ——
扩展不参与它的排队流程，只是等你看到列表之后把数据读走。

**Q：导入的评论几乎全是「B 站上已经没有这条了」，正常吗？**
正常。aicu 是历史存档，里面很多是你早就删掉的评论。这种情况接口返回 `12022`，
扩展按「已经没了」记账并把它从导入清单摘掉，**不会重复处理**，
所以一遍跑完之后剩下的才是真正需要删的。已经躺在本扩展「已删除」归档里的，
合并时还会被直接跳过，连那一次请求都省了。

## 六、文件结构

```
bili-comment-keeper/
├── manifest.json            扩展清单（MV3）
├── src/
│   ├── recorder-main.js     主世界（B站）：挂钩 fetch/XHR 抓评论 id
│   ├── aicu-main.js         主世界（aicu.cc）：顺手读走页面已加载的历史评论列表
│   ├── content.js           隔离世界：把主世界抓到的消息转发给扩展后台
│   ├── background.js        service worker：写书签、维护索引、存 aicu 导入、更新角标
│   ├── shared.js            公共：设置、书签读写、索引与 aicu 清单、链接解析、错误码翻译
│   └── ui.css               三个页面共用的样式
├── popup/                   工具栏弹窗（计数、最近记录、入口）
├── clean/                   一键清除面板 + aicu 导入区
├── options/                 设置页
├── test/                    零依赖回归测试（云同步分片、import/HTML 接线、aicu 导入）
├── .github/workflows/       持续集成：每次推送自动校验语法与清单
├── README.md
├── CHANGELOG.md             版本变更记录
├── LICENSE                  MIT
├── .editorconfig            统一编辑器风格
├── .gitattributes           统一换行符（LF）
└── .gitignore
```

零依赖、零构建：没有 npm、没有打包步骤，改完源码直接在 `chrome://extensions/` 点重新加载就生效。
回归测试同样零依赖：`node test/sync-index.test.mjs`、`node test/wiring.test.mjs`、`node test/aicu.test.mjs` 直接就能跑。

## 七、卸载 / 清理
